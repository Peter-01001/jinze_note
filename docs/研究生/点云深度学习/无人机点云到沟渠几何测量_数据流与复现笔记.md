### 具体做了什么

1. 在XY平面用PCA找点云的主要延伸方向。
2. 沿主要方向建立临时UV坐标。
3. 按60×60米的格子划分，少于1,000点的格子不保存。
4. 将每格的点保存成独立LAS，保留原始点坐标及点记录。

**PCA**：此处用于自动找出点云长轴方向。**UV**：顺着长轴和垂直长轴的临时坐标，类似把透明方格纸转到与沟渠平行，仅用于判断点属于哪个格子。

### 输入在哪里

脚本查找根目录下以`block_`开头的子目录，再读取各子目录中的`.las`或`.laz`，例如第4步列出的七份001号分类文件。也支持没有此类子目录时处理根目录本身。

### 实际处理

1. 根据文件名识别类别，不依赖LAS内部已有的classification来决定本脚本的标签。

3. 提取XYZ、RGB和强度。RGB超出255时按代码缩放、取整并限制到0—255；缺少颜色或强度时填0。
4. 把同一块中的各类别点拼接起来，不把所有块合并成一个大文件。

### 本次核对结果与009号块的问题

18个目录的分类LAS点数之和都等于对应NPY行数；每类最多256个均匀抽取行的XYZ、RGB、强度、标签，与当前转换规则一致。**这是内容核验，不是重新执行转换或恢复历史运行日志。**

001号例子：源块830,944点，分类LAS与合并NPY都是829,565点，少1,379点；缺失原因未留有操作记录，不应擅自解释为噪声清理。

**009号存在已确认的标签冲突：**

```text
/Volumes/高标准农田/点云/雷达数据集/block_009/背景.las
/Volumes/高标准农田/点云/雷达数据集/block_009/支渠.las
/Volumes/高标准农田/点云/雷达数据集/merged_output/block_009.npy
```

## 第9步：加载权重，对整场景预测类别

### 预测脚本

```text
/Volumes/高标准农田/点云/Pointnet_Pointnet2_pytorch-master/predict_farmland.py
```

### 输入文件

```text
/Volumes/高标准农田/点云/雷达数据集/路南.npy
/Volumes/高标准农田/点云/Pointnet_Pointnet2_pytorch-master/log/sem_seg/farmland_exp/checkpoints/best_model.pth
```

模型结构默认导入：

```text
/Volumes/高标准农田/点云/Pointnet_Pointnet2_pytorch-master/models/pointnet2_sem_seg.py
```

### 操作与效果

1. 在XY平面生成边长8.0、步长4.0的窗口。
2. 每窗抽4,096点，生成与训练一致形式的9维特征；全局归一化的参考范围来自当前预测场景。
3. 模型输出采样点的各类概率。
4. 用加权XYZ最近邻，把采样点概率传播给窗口全部点。
5. 对重叠窗口的概率取平均，选择最大概率类别，并保存该概率为置信度。

当前参数：

| 参数 | 当前值 | 意义 |
| --- | --- | --- |
| `BLOCK_SIZE` | 8.0 | 预测窗口边长，坐标为米时即8米 |
| `STRIDE` | 4.0 | 窗口移动步长 |
| `NUM_POINT` | 4096 | 每窗送入模型的采样点数 |
| `MIN_POINTS_IN_WINDOW` | 64 | 建立常规窗口的最少点数条件 |
| `BATCH_WINDOW` | 8 | 每批处理的窗口数 |
| `Z_WEIGHT` | 1.5 | 最近邻传播中高度差的权重 |

### “明显改善阴影”和XY→XYZ

代码注释明确针对“树影被分成树”。只使用XY传播时，地面点可能继承平面位置接近、但高度不同的树冠采样点的预测概率。

当前传播距离为：

```text
距离平方 = Δx² + Δy² + (Z_WEIGHT × Δz)²
```

因此当前1.5使高度差平方项乘2.25。函数签名默认2.0，但主流程显式传入全局1.5，实际使用1.5。

这里修改的是**预测后的概率传播距离**，不是移动原始点，也不是照片去阴影；模型本身原来就使用XYZ，滑窗仍然按XY建立。

手写笔记记录Z_WEIGHT测试1.5、2.0、3.0中1.5最优，BLOCK_SIZE测试10、8、6中8最优。当前代码值与此一致，但缺少对应对比记录，不能独立确认最优性或改善幅度。

![只按XY与按加权XYZ选择传播邻居的机制示意](assets/pointcloud-flow/03-xyz-propagation.png)
